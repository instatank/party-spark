# PartySpark — working notes

One lesson per file, one-line summary at the top of each. These record what was
tried, what broke, and what the fix was — not just the final state — so a later
session can pick the project up without re-deriving context.

Conventions:
- Filename: `NN-short-slug.md`, numbered in the order the lesson was learned.
- First line: `> **Lesson:** <one-line summary>`.
- Update an existing note instead of writing a near-duplicate; delete notes that
  turn out to be wrong.
- Architecture/state-of-the-world docs belong in `CLAUDE.md`, not here. Notes
  are for *lessons* (surprises, failures, fixes).
